# CLI Utility Specification: Markdown Link Checker

## 1. Objective

Build a cross-platform CLI utility that recursively scans a given directory, finds Markdown files, extracts links, and checks:

- whether local files and directories exist;
- whether `file://` URIs resolve correctly;
- whether external HTTP/HTTPS resources are reachable;
- whether local Markdown anchors exist.

The utility must produce a readable, colored report and return appropriate exit codes for CI usage.

## 2. Technology Stack

Implement the utility in Python 3.11+.

Allowed dependencies:

- `httpx` for HTTP requests;
- `rich` for tables, colors, and progress display;
- `typer` for the CLI;
- `pytest` for testing.

Define the project configuration and dependencies in `pyproject.toml`.

The installed command must be:

```bash
mdcheck
```

## 3. Scope

The first version includes:

- discovering `.md` and `.markdown` files;
- extracting Markdown links;
- checking local paths;
- checking `file://` URIs;
- checking HTTP/HTTPS links;
- checking Markdown anchors;
- a colored console report;
- a live progress indicator while checks run;
- a JSON report;
- concurrent HTTP checks;
- CI-compatible exit codes;
- unit and integration tests.

The first version does not include:

- checking image links;
- executing JavaScript on external pages;
- validating the content of external pages;
- full Markdown rendering;
- automatically fixing links;
- checking URLs dynamically generated by HTML or JavaScript.

## 4. Command-Line Interface

Main command:

```bash
mdcheck [PATH] [OPTIONS]
```

`PATH` may be:

- a directory to scan recursively;
- a single Markdown file;
- the current directory when omitted.

Examples:

```bash
mdcheck .
mdcheck docs/
mdcheck README.md
mdcheck . --timeout 10 --workers 8
mdcheck . --no-external
mdcheck . --format json --output report.json
```

Options:

```text
--timeout FLOAT          Timeout for one HTTP request; default: 5 seconds
--workers INTEGER        Maximum concurrent HTTP checks; default: 10
--retries INTEGER        Retry count for transient failures; default: 1
--no-external            Do not check HTTP/HTTPS links
--no-local               Do not check local links
--check-anchors           Check Markdown anchors; enabled by default
--no-check-anchors        Do not check anchors
--include GLOB            Additional include pattern; may be repeated
--exclude GLOB            Exclude pattern; may be repeated
--ignore-url PATTERN      Ignore URL by glob or regex; may be repeated
--user-agent STRING       HTTP User-Agent value
--format FORMAT           Report format: console or json; default: console
--output PATH             Write the report to a file
--no-color                Disable ANSI colors
--quiet                   Show only errors and the summary
--verbose                 Show every checked link
--version                 Show the program version
--help                    Show help
```

Default exclusions:

```text
.git/**
node_modules/**
.venv/**
venv/**
dist/**
build/**
__pycache__/**
```

User-supplied `--exclude` patterns extend the default list.

## 5. File Discovery

When given a directory, the utility must:

1. Recursively find files with `.md` and `.markdown` extensions.
2. Match extensions case-insensitively.
3. Not follow directory symlinks by default.
4. Skip default and user-supplied exclusions.
5. Gracefully handle empty directories, permission errors, and broken symlinks.

Read files as UTF-8. Record a decoding failure as a file error without aborting the whole scan.

Results must be deterministic: sort by source path and then by line number.

## 6. Supported Links

Extract standard inline Markdown links:

```markdown
[Documentation](docs/guide.md)
[Website](https://example.com)
[Local file](file:///Users/user/file.txt)
[Section](#installation)
[Other section](guide.md#configuration)
```

Support reference links:

```markdown
[Documentation][docs]

[docs]: ./guide.md
```

Support autolinks:

```markdown
<https://example.com>
<file:///tmp/example.txt>
```

Support URLs in HTML anchors:

```html
<a href="https://example.com">Example</a>
```

Do not check:

- images such as `![alt](image.png)`;
- links inside fenced code blocks;
- links inside inline code;
- links inside HTML comments;
- empty links;
- syntactically incomplete links;
- `mailto:`, `tel:`, `javascript:`, and `data:` URLs.

Mark template links such as `${BASE_URL}/docs` and `{{ url }}` as `SKIPPED`, not broken.

Store the following data for every extracted link:

- source Markdown file;
- line number;
- link text;
- original target;
- normalized target;
- link type.

## 7. Link Classification

Supported link types:

- `LOCAL_FILE`;
- `LOCAL_DIRECTORY`;
- `LOCAL_ANCHOR`;
- `FILE_URI`;
- `HTTP`;
- `HTTPS`;
- `UNSUPPORTED`;
- `TEMPLATE`;
- `INVALID`.

Classification rules:

- `http://...` → `HTTP`;
- `https://...` → `HTTPS`;
- `file://...` → `FILE_URI`;
- `#section` → `LOCAL_ANCHOR`;
- `guide.md#section` → local file with an anchor;
- `/path/file.md` → absolute local path;
- `../guide.md` → relative local path;
- paths such as `C:\docs\guide.md` must work correctly on Windows.

## 8. Local Link Validation

### 8.1 Relative Paths

Resolve every relative path against the directory containing the Markdown file in which the link appears.

Given:

```text
project/
├── README.md
└── docs/
    ├── index.md
    └── guide.md
```

This link in `docs/index.md`:

```markdown
[Guide](guide.md)
```

must resolve to `project/docs/guide.md`, not `project/guide.md`.

### 8.2 Normalization

Before checking a local path:

1. Separate the fragment after `#`.
2. Separate the query after `?`, when present.
3. URL-decode the path, including `%20` and Unicode percent-encoding.
4. Normalize `.` and `..` segments.
5. Preserve path casing.
6. Do not treat the fragment as part of the filename.

For example:

```markdown
[File](../My%20Documents/report.pdf#page=2)
```

checks `../My Documents/report.pdf` relative to the source Markdown file.

### 8.3 Directories

A link to an existing directory is valid. The checker does not need to search for `index.md` inside that directory.

### 8.4 Symbolic Links

A symlink is valid when its final target exists. A broken symlink is broken.

### 8.5 Paths Outside the Scan Root

A local link may leave the scan root through `../`, because it may legitimately reference a neighboring file. The utility only checks existence and never modifies the target.

## 9. `file://` Validation

Support:

- percent-encoding;
- Unix paths;
- Windows drive letters;
- the `localhost` host.

Examples:

```text
file:///tmp/report.pdf
file:///C:/docs/report.pdf
file://localhost/tmp/report.pdf
```

Do not access remote resources represented by `file://host/path`. Mark them as `SKIPPED` with the message `remote file URI is unsupported`.

## 10. Anchor Validation

For links such as:

```markdown
[Section](#installation)
[Section](guide.md#installation)
```

the utility must:

1. Verify that the target Markdown file exists.
2. Extract its headings.
3. Generate a slug for every heading.
4. Check whether the requested fragment exists.

Minimum slug-generation rules:

- convert text to lowercase;
- remove Markdown formatting;
- remove punctuation;
- replace spaces with `-`;
- collapse consecutive spaces into one `-`;
- preserve Unicode letters;
- append `-1`, `-2`, and so on to duplicate headings.

Example:

```markdown
# Installation Guide
```

generates `#installation-guide`.

An empty fragment represents the beginning of the document and is valid.

Keep slug generation in a dedicated function and cover it with tests.

## 11. HTTP/HTTPS Validation

### 11.1 General Algorithm

For every unique normalized URL:

1. Send a `HEAD` request.
2. Follow redirects.
3. If `HEAD` does not return a successful status (any code outside `2xx`/`3xx` — not only `405 Method Not Allowed` or `501 Not Implemented`), retry with `GET`. Some servers (observed: Figma) answer `HEAD` with an unrelated error status while `GET` succeeds, so the fallback must not be restricted to the two codes the general case suggests.
4. Stream fallback `GET` responses instead of downloading the full body.
5. Read at most the first 64 KiB.
6. Use a shared connection pool.
7. Run checks concurrently while respecting `--workers`.

Request a duplicated URL only once, but include every occurrence in the report.

### 11.2 Redirects

Follow no more than five redirects.

- redirect ending at a successful page → `OK`;
- redirect loop → `ERROR`;
- redirect limit exceeded → `ERROR`;
- redirect ending at an unavailable resource → status of the final failure.

Show the final URL in verbose mode.

### 11.3 Timeouts

Configure separate timeout categories for:

- connection;
- reading;
- writing;
- acquiring a pooled connection.

The `--timeout` value may be applied to all four categories.

A timeout for one URL must not stop the scan. Assign that result `TIMEOUT`.

### 11.4 Retries

Retry only transient failures:

- timeout;
- connection reset;
- potentially transient DNS or network errors;
- HTTP `429`;
- HTTP `502`, `503`, and `504`.

Do not retry:

- `400`;
- `401`;
- `403`;
- `404`;
- other clearly permanent failures.

Use a short exponential backoff. Honor `Retry-After`, subject to a configured maximum delay.

### 11.5 HTTP Result Classification

- `200–299` → `OK`;
- `300–399` → `OK` when redirection ends successfully;
- `401` → `WARNING`;
- `403` → `WARNING`;
- `404`, `410` → `BROKEN`;
- `429` after retries are exhausted → `WARNING`;
- all other `400–499` responses → `BROKEN`;
- `500–599` → `BROKEN`;
- DNS failure → `ERROR`;
- TLS failure → `ERROR`;
- connection refused or reset → `ERROR`;
- timeout → `TIMEOUT`;
- malformed URL → `INVALID`.

Statuses `401` and `403` do not prove that a resource is missing: it may require authentication or block automated clients.

### 11.6 HTTP Headers

Use a User-Agent such as:

```text
mdcheck/<version> (+https://example.invalid/mdcheck)
```

Also send:

```text
Accept: text/html,application/xhtml+xml,*/*
```

Do not send cookies, tokens, or authentication data.

## 12. Result Statuses and Model

Supported statuses:

```text
OK
WARNING
BROKEN
TIMEOUT
ERROR
INVALID
SKIPPED
```

Every result contains:

```text
source_file
line
link_text
original_target
normalized_target
link_type
status
http_status
message
final_url
elapsed_ms
```

Optional fields must be `null` in JSON.

## 13. Console Report

### 13.1 Progress Indicator

While files are scanned and links are checked, show a live progress bar
(spinner, description, bar, percentage, elapsed time) tracking how many of
the discovered links have been resolved so far:

```text
⠋ Checking links... ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  42% 0:00:02
```

The progress indicator:

- is written to stderr, never to stdout, so it never corrupts `--format json`
  output or a report written with `--output`;
- advances once per extracted link — for local, anchor, and `file://` checks
  as each is resolved synchronously, and for HTTP/HTTPS checks as each
  distinct URL's request completes (a URL shared by several links advances
  the bar once for every occurrence at that moment, since they all resolve
  together);
- is automatically disabled when `--quiet` is used or stderr is not a TTY
  (e.g. redirected to a file or a CI log), so it never leaves partial escape
  sequences in captured output.

### 13.2 Summary and Problems Table

Print a summary by default:

```text
Markdown Link Checker

Scanned:  24 files
Found:    138 links
Checked:  121 unique targets
Broken:   3
Warnings: 2
Skipped:  4
Duration: 2.84s
```

Then print a table of problems:

```text
┏━━━━━━━━━━━━━━━━━━━┳━━━━━━┳━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━┓
┃ File              ┃ Line ┃ Status   ┃ Details          ┃ Target             ┃
┡━━━━━━━━━━━━━━━━━━━╇━━━━━━╇━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━┩
│ docs/start.md     │ 18   │ 404      │ Not Found        │ https://...        │
│ README.md         │ 42   │ MISSING  │ File not found   │ docs/old-guide.md  │
│ docs/api.md       │ 71   │ TIMEOUT  │ timeout after 5s │ https://...        │
└───────────────────┴──────┴──────────┴──────────────────┴────────────────────┘
```

`Target` is the last column, since it is the field most likely to be long
(full URLs, deep relative paths). Neither `File` nor `Target` is truncated
with an ellipsis: both wrap onto additional lines instead of losing
information.

The table fits itself to the real terminal width (detected via the terminal
size when stdout is a TTY and `--output` is not used; a fixed fallback width
is used otherwise, e.g. when writing to a file or a non-interactive
pipe/CI log). `File`, `Details`, and `Target` share that width
proportionally rather than any one of them claiming its full, unbounded
content width — `Target` always receives the largest share, so it is the
first column to grow when there is extra room and the last to be squeezed
when the terminal is narrow.

Colors:

- green for `OK`;
- yellow for `WARNING` and `SKIPPED`;
- red for `BROKEN`, `ERROR`, and `INVALID`;
- magenta or bright yellow for `TIMEOUT`.

Automatically disable colors when stdout is not a TTY or when `--no-color` is used.

Do not list successful links individually in normal mode. Show every result with `--verbose`.

## 14. JSON Format

Example:

```json
{
  "summary": {
    "files_scanned": 24,
    "links_found": 138,
    "unique_targets_checked": 121,
    "ok": 127,
    "warnings": 2,
    "broken": 3,
    "timeouts": 1,
    "errors": 1,
    "invalid": 0,
    "skipped": 4,
    "duration_ms": 2840
  },
  "results": [
    {
      "source_file": "docs/start.md",
      "line": 18,
      "link_text": "Old documentation",
      "original_target": "https://example.com/old",
      "normalized_target": "https://example.com/old",
      "link_type": "HTTPS",
      "status": "BROKEN",
      "http_status": 404,
      "message": "Not Found",
      "final_url": "https://example.com/old",
      "elapsed_ms": 143
    }
  ]
}
```

With `--format json`, stdout must contain valid JSON only. Send progress and diagnostic messages to stderr.

## 15. Exit Codes

```text
0 — no problematic links were found
1 — at least one BROKEN, TIMEOUT, ERROR, or INVALID result was found
2 — startup or configuration error
```

Exit code `2` applies when, for example:

- the input path does not exist;
- the input path cannot be accessed;
- a CLI option has an invalid value;
- the file specified by `--output` cannot be written.

`WARNING` and `SKIPPED` results alone must not produce exit code `1`.

Recommended project structure:

```text
markdown-link-checker/
├── pyproject.toml

│   └── mdcheck/

│       ├── http_checker.py

└── tests/
    ├── fixtures/

    ├── test_parser.py
    ├── test_local_checker.py
    ├── test_anchor_checker.py
    ├── test_http_checker.py
    ├── test_reporter.py
    └── test_cli.py
```

Component responsibilities:

- `scanner.py`: file discovery;
- `parser.py`: link extraction and source line detection;
- `local_checker.py`: local path resolution and validation;
- `anchor_checker.py`: anchor extraction and validation;
- `http_checker.py`: asynchronous requests, retries, and redirects;
- `models.py`: enums and dataclasses;
- `reporter.py`: console and JSON reports;
- `cli.py`: arguments and exit codes.

Keep parsing, validation, and reporting separate so they can be tested independently.

## 17. Error Handling

One invalid link or unreadable file must not terminate the entire scan. Record the failure as a result and continue.

Global termination is acceptable only when execution cannot start or continue, for example:

- the root path does not exist;
- the root directory cannot be read;
- configuration is invalid;
- an unexpected internal exception occurs.

On `Ctrl+C`:

- cancel active tasks cleanly;
- print a short message to stderr;
- return exit code `130`.

Do not print a traceback in normal mode. A traceback is allowed in debug mode.

## 18. Testing

All network tests must use a mocked HTTP transport or a local test server. Tests must not depend on the public internet.

### 18.1 Local Paths

- existing file;
- missing file;
- link relative to a nested Markdown file;
- path containing `../`;
- filename containing a space and `%20`;
- Unicode path;
- fragment excluded from the filename;
- query excluded from the filename;
- absolute path;
- existing directory;
- broken symlink;
- `file://` URI;
- Windows path.

### 18.2 Parsing

- inline link;
- reference link;
- autolink;
- HTML `href`;
- multiple links on one line;
- multiline Markdown link;
- URL containing parentheses;
- percent-encoded URL;
- image is not checked;
- link in inline code is not checked;
- link in a fenced code block is not checked;
- link in an HTML comment is not checked;
- template link receives `SKIPPED`.

### 18.3 Anchors

- anchor in the current file;
- anchor in another file;
- missing anchor;
- heading containing spaces;
- Unicode heading;
- duplicate headings;
- Markdown formatting inside a heading.

### 18.4 HTTP

- `200`;
- `204`;
- redirect to `200`;
- redirect loop;
- `401`;
- `403`;
- `404`;
- `429` with retry;
- `500`;
- timeout;
- DNS failure;
- TLS failure;
- `HEAD` returning any non-`2xx`/`3xx` status (not only `405`/`501`) falls back to `GET`;
- duplicate URL is requested once;
- concurrency limit is respected;
- the progress callback fires exactly once per link, including duplicate and `--ignore-url`-skipped URLs, and the total matches the number of links checked.

### 18.5 CLI

- current directory by default;
- single input file;
- nonexistent path;
- `--no-external`;
- `--no-local`;
- `--format json`;
- `--output`;
- correct exit codes;
- no ANSI sequences with `--no-color`;
- JSON remains valid when individual links fail;
- JSON remains valid on stdout even when the progress indicator is active;
- the progress indicator is disabled when `--quiet` is used or stderr is not a TTY;
- the problems table fits within the detected terminal width at several
  widths, and `Target` receives more width than `File` when both compete
  for space.

## 19. Acceptance Criteria

The implementation is complete when:

1. The package can be installed with:

   ```bash
   pip install -e .
   ```

2. The installed command is available:

   ```bash
   mdcheck --help
   ```

3. Relative links are resolved against the directory of the containing Markdown file.
4. HTTP requests have timeouts, bounded concurrency, and network error handling.
5. `HEAD` automatically falls back to `GET` when `HEAD` is unsupported.
6. One problematic file or URL does not stop the whole scan.
7. Console and JSON reports contain the source path, line number, target, and failure reason.
8. Exit codes comply with this specification.
9. All required tests pass:

   ```bash
   pytest
   ```

10. Formatting and static checks pass:

    ```bash
    ruff check .
    ruff format --check .
    ```

11. `README.md` documents installation, usage examples, exit codes, and known limitations.
